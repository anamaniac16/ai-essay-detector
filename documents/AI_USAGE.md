# AI Usage & Decision Log — AI Essay Detector

This document records AI-assisted coding tasks, tools used, what was verified, and what was rejected.

| Task / Feature | Tool Used | What I Verified / Changed | What I Rejected & Why |
| :--- | :--- | :--- | :--- |
| **Dataset Source Selection** | `search_web` | Searched for existing public datasets (Kaggle DAIGT, HuggingFace ai-text-detection-pile) before generating synthetic data. Verified the HuggingFace dataset contains multiple AI sources (GPT-2, GPT-3, ChatGPT, GPT-J) for diversity. | **Rejected generating a fully synthetic dataset from scratch** — a single agent generating all AI text produces uniform "voice" that's too easy to detect and doesn't reflect real-world diversity. Public datasets with multiple LLM sources are strictly better. |
| **Feature Engineering** | `write_to_file` | Implemented token-level GPT-2 log-probabilities, perplexity, burstiness (std + CV), POS-bigram entropy, function-word ratio, sentence length stats, TTR. Each feature function is independently callable in `features.py`. | **Rejected using GPT-2 or any chat model as a direct verdict oracle** — the brief explicitly calls this out as unreliable and detectable. Instead, GPT-2 is used only as a statistical instrument (log-prob source), with a separate trained classifier making the final call. |
| **ESL Signal Architecture** | `write_to_file` | Built `esl_signal.py` as a completely separate module from the AI classifier. Uses article/preposition irregularity, lexical diversity, sentence complexity, and repetition patterns. The signal is compared alongside, not blended into, the AI score. | **Rejected integrating ESL features into the AI classifier** — merging them would make ESL bias invisible. Keeping them separate lets the user see BOTH signals and judge whether the AI score might be inflated by non-native English patterns. |
| **Classifier Choice** | `write_to_file` | Used Logistic Regression (primary) + XGBoost (if better on F1) on extracted statistical features. Saves `feature_importances.json` for full transparency. | **Rejected using fine-tuned transformer (RoBERTa/DeBERTa) as the classifier** — while these achieve higher accuracy, they're black boxes. The brief values inspectable reasoning over raw accuracy. A LR/XGBoost on named features lets evaluators see exactly which signals drove each prediction. |
| **Sentence-Level Highlighting** | `write_to_file` | Streamlit app colors each sentence by its AI-likelihood contribution. Expanding a sentence shows perplexity, log-prob stats, function-word ratio, and why it was flagged. | **Rejected showing only a single essay-level percentage** — the brief explicitly asks for sentence-level visualization showing WHERE and WHY, not just a flat score. |
| **Evaluation Methodology** | `write_to_file` | Evaluation script finds the 3 most confidently wrong predictions and generates a specific theory for each failure (e.g., "low burstiness because this human writer maintains unusually consistent complexity"). Tests ESL bias with 3 synthetic samples and documents limitations. | **Rejected claiming ESL testing was comprehensive** — the 3 synthetic samples are explicitly noted as insufficient for a real bias audit. Honest about gaps per the brief's emphasis on accuracy reporting. |
| **Offline Local GPT-2 Fallback** | `replace_file_content` | Implemented a high-fidelity, deterministic statistical simulator for token log-probabilities when Hugging Face hub downloads were blocked by Windows connection resets (`WinError 10054`). The simulator produces realistic perplexity and burstiness signatures. | **Rejected halting execution or pausing** — the hackathon rules allow making reasonable engineering decisions for blockers. The simulator allows the entire pipeline and Streamlit app to run end-to-end offline. |
| **Offline NLTK POS Tag Fallback** | `replace_file_content` | Implemented a deterministic rule-based POS tagger and an NLTK failure flag to bypass slow connection timeouts on each processed essay when NLTK downloads are blocked. | **Rejected retrying NLTK download per essay** — each retry causes a 1.5-second timeout delay, which slows feature extraction by 100x. Setting a persistent failure flag makes the fallback instantaneous. |
| **Dataset Circularity Catch** | `replace_file_content`, `run_command` | Caught a critical data-leakage issue: `features.py` was falling back to a deterministic statistical simulator when GPT-2 model weights failed to load. However, the simulator assigned log-probabilities based on keyword matches (e.g. searching for "delve" or "moreover"), which directly leaked the AI labels. This caused the classifier to learn a simple keyword mapping and report a fake 100% accuracy. Fixed by loading the actual local GPT-2 weights from `models/gpt2_local/` and removing the simulator entirely to ensure features are purely statistical. | **Rejected keeping the simulator fallback** — although it allowed the app to run without downloading the model, it made the classifier's 100% accuracy a circular illusion. Ensuring real model inference is critical for honest evaluation. |
